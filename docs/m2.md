# M2 — propose, gate, KEEP / DROP

Soft does not speak HTTP. `scripts/propose_minimax.py` reads
`~/.config/aura-build/minimax.env` (`MINIMAX_API_KEY_FILE`,
`MINIMAX_MODEL`, default `MiniMax-M3`). The default base URL is
`https://api.minimax.cn/v1`. If the env file says `api.minimaxi.com`, the
script rewrites it to `api.minimax.cn` and prints `PROPOSE_BASE`. It never
calls `api.minimaxi.com`. The key file is not in the repo and is never
printed.

The script writes one line `(lambda (age own other) ...)`. Soft gates that
string, swaps it into `ev:choose`, and races it against `ev:shadow` (the
current main) on the same seed.

## Gate

Rejected before swap: not a `(lambda (age own other) ...)`, or the text
contains `set!`, `vector-set!`, `display`, `mutate`, `eval`, `load`,
`shell`, `http`, `ev:reset`, `ev:tick`, `ev:race`, or `fiber:`.

Swapped, then healed, when the probe `(ev:choose 4 1 2)` is not 0 or 1
(`propose_heal`).

## KEEP rule

`KEEP` only when `trial > base`. Equal scores `DROP` and `heal!` the
pre-trial snapshot (`lower-score-rollback`). The kept string becomes
`*main-body*` and the next round's shadow.

Worldline stamp uses the same rule as M1: `fiber_live` only on the
cooperative scheduler backend, when every race spawned two distinct fibers
and both joins returned numbers. The CLI thread backend shares one mutable
world, so it runs the two thunks in order and stamps `host-sequential`
(#4946); the fixture smoke then prints `joins=0/0`.

## QD KEEP rule (v0.2, #4946)

The live M2 rule is no longer "strictly greater than the main". `ev:choose`
holds a body, but the decision is a MAP-Elites archive from `std/qd`:

```scheme
(require "std/qd" all:)
(define m (qd:map-elites (hash "descriptors" (list (list "throughput" 114 122 6)
                                                  (list "stops" 50 80 6))
                              "quality" "score" "seed" seed)))
(qd:insert! m cand score (list throughput stops))   ; #t = KEEP, #f = DROP
```

* descriptors: throughput and stops of the 60-tick run at sim seed `20261005`
* quality: the integer score (higher is better), so a cell never trades a
  better body for a worse one
* KEEP: the cell was empty or the newcomer is better (`cell-new-or-better`)
* DROP: a dominated cell (`cell-dominated`), a gate rejection, or a
  constraint rejection
* champion: `(qd:best m)`, stamped into `ev:choose` and replayed with the
  tape on

The safety boundary is the M2 gate, not a promise: every candidate goes
through `ev:apply-body!` (forbidden tokens, length, prefix, `hot-strategy`
swap, 0/1 probe, heal on a bad probe), then a score floor (`EVOLVE_QD_FLOOR`,
default `-820`) and the world invariants (throughput ≥ 0, stops ≥ 0,
queues ≥ 0). A rejected candidate is logged as `ROLLBACK` and never
inserted. `qd_m2.aura` also feeds a `set!` body through that path on
purpose: it is a gate DROP in the tape. The score floor is exercised by
long-green mutations (`-894`, `-1003`), also visible as
`constraint:score-floor` DROPs.

The policy family is a template, not free text: `(lambda (age own other) ...)`
with genes `g` (force-switch age), `a` (earliest queue-rule age) and `c`
(the queue rule). 128 members are swept, then 112 mutated children are tried.
A mutation can only produce another member of the family, so the gate stays
green and the archive still sees the full descriptor spread.

Measured, 5 search seeds (`EVOLVE_QD_SEED=1..5`), sim seed `20261005`,
horizon 60, 241 evaluations per seed:

| evals | elites | coverage (6×6) | best | old champion |
|-------|--------|----------------|------|--------------|
| 241   | 7      | 19%            | -647 | -650         |

All five seeds give the same archive: the family is small and the 128-member
sweep already reaches the best body, so mutation has nothing left to add.
Coverage stays at 19% because the single intersection is saturated
(throughput 117–120 of 120) and its behaviour band only intersects 7 of the
36 declared cells. That is a property of the world, not a search failure;
M2 has no coverage target.

The old single-champion path (`propose.aura`, `burn.aura`, `pk.aura`) is
kept as the A/B baseline. It still prints `KEEP reason=higher-score-stamp`
and `DROP reason=lower-score-rollback`, and `smoke_m2.sh` still pins
`-764 / -2289 / -650`.

## 中文（QD）

M2 的实况规则改成 `std/qd` 的 `qd:map-elites`：描述子是（吞吐，停车次数），
质量是整数 score，`qd:insert!` 返回真就是 KEEP（格子空或更好），返回假就是
DROP（格子被压过、门禁拒绝或约束拒绝）。冠军取 `qd:best`，装回 `ev:choose`
后带 tape 重放。安全边界原样保留：每个候选都走 `ev:apply-body!` 的禁用词
门禁、swap 和 0/1 探针，再过分底线和世界不变量；被拒绝的只记 `ROLLBACK`，
绝不进档案。五个搜索种子固定复现 241 次评估、7 个 elite、最好 `-647`
（原冠军 `-650`）。覆盖率 19% 是路口饱和导致的窄行为带，M2 不要求覆盖率。
老的单冠军脚本保留作 A/B 基线。

## Live

`bash scripts/smoke.sh` calls MiniMax once when the key file exists, then
`m2_live.aura`. Any honest tag (`propose_keep`, `propose_drop`,
`propose_heal`, `propose_reject`) prints `EVOLVE_M2_PROPOSE_LIVE_OK`.
No key prints `EVOLVE_M2_PROPOSE_LIVE_SKIP` and is success. A failed HTTP
call, or a Soft error, is `EVOLVE_M2_PROPOSE_LIVE_FAIL`.

One measured live lambda lost to agg (`RACE base=-764 trial=-820`), so
the stamp was `DROP` plus `HEAL`, and the line was
`host-sequential backend=0 joins=0/0`. That is a successful gate, not a keep.
