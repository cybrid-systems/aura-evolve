# M3 — two intersections, evolution tape, sustained PK

M0/M1/M2 still own one intersection. M3 does not change that law and does
not load into `m0_smoke.aura`. The new world is `soft/evolve/grid.aura`:
a corridor of two nodes. Each node has its own phase, green age, and NS/EW
queues. One LCG feeds both. Each tick arrives on both nodes (four draws),
then both choose, then both serve up to 2. The score is one integer:

`throughput - queue_pen - stop_pen`

across both nodes. Tick 24 still does `(set! *g-stop-w* 3)` and prints
`MUTATE`. Earlier stop penalty is not retconned.

A shared policy passes the same chooser to both nodes. A per-node policy
passes a different chooser to each node. The per-node line in the smoke is
host-sequential on purpose. The shared agg-vs-calm race is the fiber race.

## Tape

Soft prints `ETAPE op=... tick=... mid=... score=... reason=...` for
`SWAP`, `HEAL`, `MUTATE`, `RACE`, `KEEP`, and `DROP`. That log is
append-only in emit order. `scripts/collect_tape.py` copies it to
`out/tape_m3.md` or `out/tape_pk.md`. `bash scripts/replay_tape.sh`
pretty-prints the newest `out/tape_*.md`. It does not rewind the world.

Snapshot `TAPE tick=` lines are still the grid state every 10 ticks of a
kept replay. They are not the decision log.

| end | `EVOLVE_M3_OK` |

The CLI reports the thread fallback (`fiber:spawn-backend` = 2), and two
threads would share one mutable Soft world; `ev:race-thunks!` therefore runs
the two thunks in order and stamps `host-sequential` (#4946). The scores
match the host-sequential probe exactly. A cooperative scheduler host would
stamp `fiber_live` only with two distinct fibers and both joins landed.

`SWAP` / `HEAL` on `ev:choose` happen before the grid race (chase body,
then an ugly pair that heals back). They are on the tape. They do not
reset grid queues.

## PK

`bash scripts/burn_pk.sh`

- `EVOLVE_PK_ROUNDS` default 4 (falls back to `EVOLVE_BURN_ROUNDS`).
- `EVOLVE_HORIZON` default 24.
- `EVOLVE_PROPOSE=0` uses `soft/evolve/fixtures/pk/{1,2,3,4}.lambda`.
- `EVOLVE_PROPOSE=1` (default) calls MiniMax once per round when
  `~/.config/aura-build/minimax_api_key` is non-empty, else the same
  fixtures. HTTP stays in `scripts/propose_minimax.py`
  (`https://api.minimax.cn/v1` only).
- Scoreboard: `out/pk_scoreboard.md`. The `WORLD` line in that file is
  copied from Soft. The script does not invent `fiber_live`.
- Tape: `out/tape_pk.md`.

Each round installs the lambda as a **shared** policy and races it against
the current main on the corridor. KEEP only when `trial > base`. A tie
DROPs and `heal!`s.

Fixture contract (horizon 24, `EVOLVE_PROPOSE=0`), pinned in `pk.aura`:

| round | body | race | stamp |
|-------|------|------|--------|
| baseline | agg | `-276` | |
| 1 | chase (`other > own`) | base `-276` trial `-237` | KEEP |
| 2 | always switch | base `-237` trial `-291` | DROP |
| 3 | always hold | base `-237` trial `-731` | DROP |
| 4 | age≥8 or chase | base `-237` trial `-237` | DROP (tie) |

`WORLD line=host-sequential backend=0 joins=0/0` (four races, run in order).
`MAIN score=-237`. `EVOLVE_PK_OK`.

Live rounds are not score-pinned. Any honest tag
(`propose_keep`, `propose_drop`, `propose_heal`, `propose_reject`) can
finish `EVOLVE_PK_OK`. The fixture script additionally requires a KEEP and
a DROP. No key is not a failure: the script uses fixtures.

## QD corridor (#4946)

`soft/evolve/qd_m3.aura` runs the same `std/qd` archive on the corridor.
A candidate is a policy pair; the archive keeps different good pairs, not one
winner.

* descriptors: corridor throughput and corridor stops at sim seed `20261005`
* grid: 6 throughput bins over `[230, 238]` × 5 stop bins over `[114, 150]`
  = 30 cells. The bounds are the operating envelope of the policy family
  measured by a calibration sweep at the same seed, not the physical bound
  `[0, 4·horizon]`: the corridor saturates (throughput 230–237 of 240), so a
  0-based grid would put every elite in two cells and measure nothing.
* quality: the corridor score. KEEP = `qd:insert!`, DROP = dominated cell,
  gate or constraint rejection.
* safety boundary: both node bodies go through `ev:apply-body!`; the pair
  must clear `EVOLVE_QD_FLOOR` (default `-1600`) and the four queue
  invariants.

Search is 865 evaluations: 128 shared members, a 24×24 lattice over
`(g, a, c)` = 576 pairs, 64 seeded random pairs, then 96 mutated pairs.

Measured, 5 search seeds, sim seed `20261005`, horizon 60:

| seed | evals | elites | coverage | best |
|------|-------|--------|----------|------|
| 1 | 865 | 24 | 80% | -1093 |
| 2 | 865 | 25 | 83% | -1095 |
| 3 | 865 | 24 | 80% | -1093 |
| 4 | 865 | 25 | 83% | -1095 |
| 5 | 865 | 25 | 83% | -1093 |

Best cell is throughput 237 / stops 117. The old M3 champion is `-1165`
(per-node agg/chase), so the best elite is 72 points better. The M2 champion
`-650` is a single intersection; the fair comparison across a two-node
corridor is per node: `-1093 / 2 = -546.5`, also better than `-650`.

The non-dominated front at seed 1 has three points: `(-1093, 117 stops)`,
`(-1145, 115)`, `(-1195, 114)`. The archive keeps the stop/score trade-off
that a single champion would have thrown away.

### Tape and report

```bash
python3 scripts/tape_from_evo_log.py out/evo_m3_s1.jsonl m3-s1 out/tape_m3_qd.txt
python3 scripts/collect_tape.py out/tape_m3_qd.txt out/tape_m3_qd.md "M3 QD tape"
aura evo report --html out/report_m3 --log out/evo_m3_s1.jsonl --run m3-s1
python3 scripts/verify_evo_tape.py out/evo_m3_s1.jsonl m3-s1 \
  out/tape_m3_qd.txt out/qd_m3_s1.txt "$AURA_BIN" out/report_m3
```

`ETAPE` rows are generated from the log only; Soft stdout is not parsed.
Every record carries an explicit parent, because `hot-strategy` swaps append
their own `mutate:rebind` rows and the CLI drops those from a run that has
its own verdicts. Only `KEEP` rows carry `objectives`, so
`aura evo log --front` is the set of archive advances.

The verifier prints, and `scripts/smoke_qd.sh` requires:

```
FRONT_SUBSET OK front=3 missing=[]
LINEAGE_MATCH OK chain=['#2', '#8', ... '#2510']
BEST_MATCH OK soft=-1093 tape=-1093
COVERAGE_MATCH OK soft=80 tape_max=80
REPORT_ARTIFACTS OK out/report_m3
VERIFY_OK
```

## 中文（QD 走廊）

`qd_m3.aura` 用同一套 `std/qd` 档案跑走廊。候选是一对策略，档案保留的是
“不一样的好”，不是唯一冠军。描述子是（吞吐，停车次数），网格 6×5 共 30 格，
边界取家族在固定种子下的运行包络 `[230,238]×[114,150]`；走廊本来就在
230–237（上限 240）饱和，用 0 起的物理网格只会把所有 elite 挤进两格，
量不出东西。865 次评估：128 个共用成员、24×24=576 个格点组合、64 个随机对、
96 个变异对。五个搜索种子覆盖率 80–83%，最好 −1093，优于原冠军 −1165；
按每路口折算 −546.5，也优于 M2 冠军 −650。种子 1 的非支配前沿有三个点
（−1093/117 停、−1145/115、−1195/114）。ETAPE 只从 evo log 生成，
并用 `scripts/verify_evo_tape.py` 与 `aura evo log --front/--lineage` 和
`aura evo report` 的产物逐项对齐。
